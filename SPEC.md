# Техническое задание v1.1
## Утилита массового изменения и восстановления цен каталога Tilda

**Проект:** ElleMexa  
**Сайт:** ellemexa.ru  
**Назначение:** внутренняя веб-утилита для владельца и менеджеров магазина  
**Версия:** MVP / v1  
**Рабочее название:** «Массовое изменение цен для Tilda»

---

# 1. Цель проекта

Разработать простую веб-утилиту, которая позволит массово менять цены товаров интернет-магазина ElleMexa без ручного редактирования карточек товаров и без ручной работы с CSV в Excel, конвертерах и других сервисах.

Текущий штатный сценарий Tilda:

1. Экспортировать каталог в CSV.
2. Корректно открыть CSV.
3. Следить за кодировкой и разделителем.
4. Найти необходимые товары.
5. Массово изменить цены.
6. Сохранить файл в правильном формате.
7. Не повредить остальные поля, изображения, UID, варианты и т. д.
8. Импортировать CSV обратно в Tilda.

Новая утилита должна оставить пользователю только понятные действия:

**выгрузить CSV → загрузить в панель → выбрать категорию → задать изменение цены → проверить результат → скачать готовый CSV → импортировать обратно в Tilda.**

Дополнительно утилита должна позволять сохранить backup измененных цен и впоследствии восстановить цены из него.

---

# 2. Основные принципы MVP

Утилита должна быть:

- простой;
- mobile-first;
- удобной в первую очередь на iPhone;
- без регистрации;
- без личного кабинета;
- без сервера и backend;
- без базы данных;
- без подключения к API Tilda;
- без AI / OpenAI API;
- без платных сервисов;
- без хранения каталога клиента;
- с обработкой файлов непосредственно в браузере пользователя.

Приложение не является полноценной системой управления каталогом или SaaS-продуктом.

Это небольшая специализированная утилита под конкретную задачу массовой работы с ценами.

## 2.1. Изменения v1.1

Следующие требования уточняют и дополняют MVP v1. Все правила безопасности, структура backup и правило неизменности `Price Old` сохраняются.

### Ограничение итоговой цены

- Максимальная допустимая итоговая цена — `10 000 000 ₽` включительно.
- Проверяется конечный результат каждой изменяемой цены для всех операций.
- Фиксированная цена должна быть больше `0` и не больше `10 000 000`.
- Если хотя бы один результат превышает максимум, preview и экспорт блокируются с понятной ошибкой.
- Чрезмерно большие и нечисловые значения также блокируются.

### Ошибки формы

- Все ошибки текущей ценовой операции показываются непосредственно перед кнопкой **«Показать изменения»**.
- При блокирующей ошибке кнопка disabled; появление ошибки не прокручивает страницу.
- Системные success, warning и error-плашки используют компактные SVG-иконки.

### Терминология и действия

- В основном интерфейсе используется **«варианты с ценой»**, а не **«строки с ценой»**.
- Основное пояснение: **«Будут изменены только цены товаров. Остальные данные останутся без изменений.»**
- Действия имеют три уровня: темная primary, светлая secondary с границей и нейтральная tertiary.
- К загрузке, скачиванию, backup, настройкам, сбросу и возврату добавляются inline SVG-иконки.
- В restore-flow используется secondary-кнопка **«Вернуться к изменению цен»**.

### Preview

- На desktop доступны **«Плитка»** и **«Таблица»**; по умолчанию открывается плитка.
- Таблица показывает фото, товар, число вариантов, текущую и новую цену и позволяет раскрыть варианты.
- На mobile всегда используются карточки, переключатель скрыт, горизонтальный scroll не требуется.
- На preview есть дополнительная sticky-панель скачивания. На iPhone она учитывает `env(safe-area-inset-bottom)` и не заменяет финальный блок действий.

### Имена файлов и состояние скачивания

- CSV: `ellemexa_<category-slug>_<operation>_<YYYY-MM-DD>_<HH-MM>.csv`.
- Backup: то же основное имя с суффиксом `_backup.json`.
- Restore: `ellemexa_<category-slug>_restore_<YYYY-MM-DD>_<HH-MM>.csv`.
- Используются локальное время, ASCII, lowercase-транслитерация и безопасные символы без пробелов.
- Операции: `discount-20pct`, `increase-15pct`, `fixed-38000rub`, `add-2000rub`, `subtract-2000rub`; десятичная точка заменяется дефисом.
- После скачивания показывается имя файла и связь пары CSV + backup.

### Визуальный стиль ElleMexa

- Используется логотип `/assets/ellemexa-logo.png` в компактном header **«Менеджер цен»**.
- Визуальный язык: fashion/minimal retail, почти черный primary, нейтральные поверхности, тонкие границы, небольшие радиусы и минимум теней.
- Page title может использовать системный serif; формы, таблицы, цены и действия остаются sans-serif.
- Зеленый, amber и красный применяются только для системных состояний.


# 7. Структура товаров и вариантов

Критически важная особенность текущего каталога:

основной товар и его размеры представлены отдельными строками.

Пример:

```text
Основной товар
Tilda UID: 366695909232
Parent UID: пусто
Category: ПАРКИ 70 см;OUTLET
Price: пусто

↓ варианты ↓

Размер 40/42
Tilda UID: 299657443112
Parent UID: 366695909232
Price: 39990.00

Размер 42/44
Tilda UID: 638555182312
Parent UID: 366695909232
Price: 39990.00
```

Такая структура непосредственно присутствует в текущем экспорте ElleMexa.

### Правило определения основной строки

Если:

`Parent UID == пусто`

строка считается основным товаром.

### Правило определения варианта

Если:

`Parent UID != пусто`

строка считается вариантом товара.

Связь:

```text
variant.Parent UID === parent.Tilda UID
```

# 8. Где находится цена

В большинстве товаров ElleMexa фактическая цена находится в строках вариантов, а не в родительской строке.

Поэтому нельзя просто менять `Price` у родительских товаров.

### Алгоритм определения изменяемых строк

Для каждого выбранного основного товара:

1. Найти все строки, где:

   `Parent UID === Tilda UID основного товара`

2. Найти среди них строки с заполненным `Price`.

3. Если такие строки есть — изменять цены этих вариантов.

4. Если дочерних вариантов с ценой нет, проверить `Price` основного товара.

5. Если цена заполнена у основного товара — изменить ее.

6. Если цена отсутствует и у родительской строки, и у вариантов — товар считается товаром без цены.

Такой товар не должен изменяться.

Пользователю необходимо показать предупреждение.

# 9. Определение категорий

Категории нельзя жестко прописывать в коде.

Они должны каждый раз извлекаться из загруженного CSV.

Причина: клиент может создавать, удалять или переименовывать категории в Tilda.

### Источник категории

Поле:

`Category`

### Несколько категорий

Один товар может находиться сразу в нескольких категориях.

Например:

```text
ПАРКИ 70 см;OUTLET
```

Такое значение присутствует в реальном экспорте.

После того как CSV уже корректно распарсен, значение `Category` необходимо дополнительно разделить по `;`.

Получаем:

```text
[
  "ПАРКИ 70 см",
  "OUTLET"
]
```

Пробелы по краям удалить.

### Выбор категории

Если пользователь выбирает:

`OUTLET`

необходимо выбрать все основные товары, массив категорий которых содержит точное значение:

`OUTLET`

в том числе товары:

`ПАРКИ 70 см;OUTLET`

### В MVP

Одна операция = одна выбранная категория.

# 10. Выключенные товары

# 15. Выбор операции с ценой

Блок:

**Как изменить цену?**

Доступны четыре операции.

## 15.1. Снизить на %

Пользователь вводит:

`20`

Расчет:

```text
newPrice = currentPrice × (1 - 20 / 100)
```

Пример:

```text
39 990 → 31 992 → 31 990
```

После расчета применяется правило округления.

---

## 15.2. Повысить на %

Пользователь вводит:

`20`

Расчет:

```text
newPrice = currentPrice × (1 + 20 / 100)
```

Пример:

```text
39 990 → 47 988 → 47 990
```

---

## 15.3. Установить фиксированную цену

Пользователь вводит:

`38 000`

Все изменяемые варианты выбранной категории получают:

`38 000`

Фиксированная цена не пересчитывается и дополнительно не округляется.

Пользователь сам указывает конечное значение.

---

## 15.4. Изменить на сумму

Пользователь выбирает:

`+` или `−`

и вводит сумму.

Пример:

```text
+ 10 000 ₽
```

Расчет:

```text
39 990 → 49 990
42 000 → 52 000
```

При уменьшении:

```text
− 10 000 ₽
```

---

# 16. Правило округления

Для вычисляемых операций:

- снижение на %;
- повышение на %;
- изменение на сумму;

конечная цена округляется до ближайших **10 рублей**.

Формула:

```text
Math.round(value / 10) * 10
```

Примеры:

```text
31 992 → 31 990
31 996 → 32 000
24 004 → 24 000
```

В интерфейсе цена отображается без копеек.

В итоговом CSV допустимо сохранять ее в формате:

```text
31990.00
```

для совместимости со структурой Tilda.

---

# 17. Поле Price Old

В MVP поле:

`Price Old`

**не изменяется.**

Если было:

```text
Price = 39 990
Price Old = 62 000
```

после акции −20%:

```text
Price = 31 990
Price Old = 62 000
```

Причина: ElleMexa уже использует `Price Old` как старую/зачеркнутую цену.

Изменение этого поля может нарушить текущую маркетинговую логику магазина.

В будущей версии можно добавить отдельную функцию управления `Price Old`.

# 23. Группировка вариантов

Не показывать 100+ размеров отдельными строками по умолчанию.

Основное представление группируется по parent-товару.

Если все варианты имеют одинаковую цену:

```text
Экошуба Milano
4 варианта

39 990 → 31 990
```

Если цены разных вариантов отличаются:

```text
от 39 990 → от 31 990
```

Добавить возможность раскрыть товар и посмотреть варианты.

В раскрытии показать:

- название/размер варианта;
- текущую цену;
- новую цену.

Для названия варианта в первую очередь использовать `Editions`.

Если его нет — использовать `Title` дочерней строки.

---

# 24. Mobile-preview

На iPhone не использовать широкую desktop-таблицу с горизонтальным скроллом как основной вариант.

Использовать карточки или компактные строки:

```text
[фото]

Экошуба Milano
4 размера

Было       Станет
39 990     31 990
```

Варианты раскрываются отдельно.

---

# 25. Проверка безопасности перед экспортом

Перед тем как активировать кнопку скачивания, приложение обязано провести внутреннее сравнение исходных и измененных данных.

## Проверить:

- количество строк не изменилось;
- количество колонок не изменилось;
- порядок колонок не изменился;
- порядок строк не изменился;
- все `Tilda UID` сохранены;
- все `Parent UID` сохранены;
- `Category` не изменен;
- `Photo` не изменен;
- `Quantity` не изменен;
- `Price Old` не изменен;
- `Editions` не изменен;
- `Description` не изменен;
- `Text` не изменен;
- `Mark` не изменен;
- `SKU` не изменен;
- `External ID` не изменен;
- остальные неизвестные поля тоже не изменены.

Разрешенное изменение только одно:

`Price`

и только у UID, вошедших в текущую операцию.

---

# 26. Важное техническое уточнение о сравнении файлов

Не требуется, чтобы итоговый CSV был побайтно идентичен исходному.

CSV-библиотека может иначе расставить кавычки или переносы строк.

Требуется **логическая идентичность значений**.

То есть после повторного parsing итогового CSV:

каждая неизменяемая ячейка должна содержать точно то же значение, что и в исходном файле.

---

# 27. Повторная проверка созданного CSV

После сериализации готового CSV приложение должно:

1. повторно распарсить созданный CSV;
2. проверить его структуру;
3. повторно сравнить его с ожидаемым результатом.

Если проверка не проходит — скачивание запрещается.

Показать hard error:

> Не удалось безопасно сформировать файл. Обнаружены непредусмотренные изменения. Исходный каталог не изменен.

---

# 28. Экспорт CSV

Итоговый CSV должен:

- использовать UTF-8;
- использовать разделитель `;`;
- сохранять исходные названия колонок;
- сохранять их исходный порядок;
- сохранять порядок строк;
- корректно экранировать `;`, кавычки и переносы строк;
- быть пригодным для обратного импорта в Tilda.

Пример имени:

`ellemexa_outlet_discount-20pct_2026-08-27_19-30.csv`

---

# 29. Backup цен

Каждая успешно рассчитанная операция изменения цен должна автоматически формировать backup в памяти приложения.

Backup не скачивается автоматически.

На preview пользователь получает отдельную кнопку:

**Скачать backup цен**

Backup нужен для последующего безопасного возврата цен после акции.

---

# 30. Формат backup

Использовать JSON.

Не использовать CSV для backup.

Пример структуры:

```json
{
  "schemaVersion": 1,
  "createdAt": "2026-08-27T19:30:00+07:00",
  "sourceFile": "store-9975565-202608271513.csv",
  "category": "Экошубы",
  "operation": {
    "type": "decrease_percent",
    "value": 20
  },
  "items": [
    {
      "tildaUid": "299657443112",
      "parentUid": "366695909232",
      "title": "Парка с натуральным мехом чернобурой лисы - Рр 40/42",
      "originalPrice": "39990.00",
      "originalPriceOld": "62000"
    }
  ]
}
```

---

# 31. Что хранится в backup

Для каждой реально измененной строки:

- `Tilda UID`
- `Parent UID`
- название для отображения;
- исходный `Price`;
- исходный `Price Old`.

Также:

- версия формата backup;
- дата создания;
- имя исходного CSV;
- категория;
- тип операции;
- значение операции.

---

# 32. Что НЕ хранится в backup

Не нужно сохранять:

- фотографии;
- описания;
- остатки;
- весь каталог;
- характеристики;
- HTML;
- все остальные поля.

Backup должен быть небольшим.

---

# 33. Важное правило восстановления Price Old

Хотя `Price Old` можно сохранить в backup как справочное исходное значение, в MVP восстановление **не должно записывать его обратно**.

Восстанавливается только:

`Price`

Причина:

за время акции клиент мог самостоятельно изменить `Price Old` в Tilda.

Возвращение старого значения из backup могло бы затереть актуальные изменения.

---

# 34. Экран после успешного расчета

После прохождения safety validation:

### Primary button

**Скачать новый CSV**

### Secondary button

**Скачать backup цен**

Рядом с backup:

> Сохраните этот файл, если захотите позже вернуть цены до акции.

Не запускать автоматическое скачивание двух файлов одновременно.

---

# 35. Инструкция после скачивания

На финальном экране показать:

### Как загрузить файл обратно

1. Откройте каталог Tilda.
2. Выберите импорт товаров из CSV.
3. Загрузите созданный файл.
4. Проверьте сопоставление полей.
5. Включите **«Обновить только существующие товары и не создавать новые»**.
6. Не включайте замену изображений.
7. Не включайте замену тегов.
8. Используйте группировку вариантов по `Parent UID`.
9. Запустите обновление.

Tilda при импорте позволяет сопоставить `Tilda UID`, `Price`, `Price Old`, `Parent UID`, `Editions` и остальные поля каталога.

В текущем интерфейсе импорта также доступны настройки «Обновить только существующие товары», замена изображений, работа с тегами и группировка по Parent UID.

# 36. Отдельный flow: восстановление цен

На первом экране присутствует secondary action:

**Восстановить цены из backup**

После нажатия пользователь переходит в отдельный сценарий.

---

# 37. Экран восстановления — шаг 1

Заголовок:

**Восстановление цен**

Первый файл:

**Загрузите актуальный CSV из Tilda**

Подсказка:

> Перед восстановлением выгрузите свежий каталог. Так изменения товаров, фотографий, размеров и остатков, сделанные после начала акции, сохранятся.

CSV проходит ту же полную валидацию, что и в основном flow.

---

# 38. Экран восстановления — шаг 2

После успешной загрузки CSV:

**Загрузить backup цен**

Поддерживается только `.json` backup, созданный данной утилитой.

После чтения показать:

```text
✓ Backup найден

Категория: Экошубы
Создан: 27.08.2026
Операция: −20%
Позиций в backup: 183
```

---

# 39. Логика восстановления

Основной идентификатор:

`Tilda UID`

Для каждого элемента backup:

1. найти строку свежего CSV с таким же `Tilda UID`;
2. если найдена — подготовить возврат `Price` к `originalPrice`;
3. `Price Old` не менять;
4. остальные поля не менять.

Категория не является ключом сопоставления.

Если товар за время акции был перенесен в другую категорию, восстановление все равно выполняется по UID.

---

# 40. Что происходит с новыми товарами и вариантами

Если после создания backup в каталоге появились новые товары или размеры:

- они отсутствуют в backup;
- их цена не изменяется при восстановлении.

Если старый вариант удален:

- его UID не будет найден;
- он пропускается;
- пользователь получает предупреждение.

---

# 41. Результат сопоставления backup

Если найдено всё:

```text
✓ Найдено 183 из 183 позиций
```

Если часть отсутствует:

```text
⚠ Найдено 179 из 183 позиций

4 позиции больше не найдены в текущем каталоге и будут пропущены.
```

Partial match не блокирует восстановление.

# 42. Preview восстановления

До создания CSV показать:

**Предпросмотр восстановления**

Например:

| Товар | Сейчас | Вернется |
|---|---:|---:|
| Экошуба Milano | 31 990 ₽ | **39 990 ₽** |

На mobile использовать те же карточки, что в основном preview.

# 43. Экспорт после восстановления

Кнопка:

**Скачать CSV с восстановленными ценами**

После формирования выполнить ту же safety validation.

Разрешено изменить только:

`Price`

и только для UID из backup, найденных в актуальном CSV.

# 44. Ошибки и валидация

Ошибки не должны быть отдельным общим flow.

Они показываются непосредственно на том экране, где возникли.

Формат:

- красная плашка для блокирующей ошибки;
- желтая/оранжевая плашка для предупреждения;
- зеленая плашка для success.

---

# 45. Блокирующие ошибки CSV

## Неподдерживаемый файл

> Поддерживаются только CSV-файлы.

---

## Файл невозможно прочитать

> Не удалось прочитать файл. Проверьте, что это CSV-экспорт каталога Tilda.

---

## Пустой файл

> В файле не найдено данных каталога.

---

## Нет header

> Не удалось определить структуру CSV.

---

## Нет `Tilda UID`

> В файле отсутствует обязательное поле Tilda UID.

Работа запрещена.

---

## Нет `Parent UID`

> В файле отсутствует поле Parent UID. Невозможно безопасно определить варианты товаров.

Работа запрещена.

---

## Нет `Category`

> В файле отсутствует поле Category.

Работа запрещена.

---

## Нет `Price`

> В файле отсутствует поле Price.

Работа запрещена.

---

## Нет `Title`

> В файле отсутствует поле Title.

Для MVP считать блокирующей ошибкой, так как без него невозможно нормально построить preview.

---

## Дублирующиеся Tilda UID

Если одинаковый `Tilda UID` встречается в нескольких строках:

> В каталоге обнаружены повторяющиеся Tilda UID. Невозможно безопасно изменить цены.

Работа запрещена.

---

## Не найдено категорий

> В каталоге не найдено категорий товаров.

Работа запрещена.

---

# 46. Предупреждения CSV

Не каждая проблема должна блокировать весь файл.

Например:

> 3 товара не имеют цены и не смогут участвовать в изменении.

Если остальные товары обработать безопасно можно — разрешить продолжить.

---

# 47. Ошибки выбранной категории

После выбора категории провести дополнительную валидацию.

### Нет товаров

> В выбранной категории не найдено товаров.

### Нет товаров с ценами

> В выбранной категории не найдено товаров, у которых можно изменить цену.

### Некорректная цена

Если у изменяемого варианта `Price` заполнен, но его невозможно преобразовать в число:

> У нескольких товаров обнаружена некорректная цена. Исправьте цены в Tilda и загрузите каталог заново.

Для выбранной операции считать блокирующей ошибкой.

---

# 48. Валидация процентов

### Снижение

Допустимое значение:

```text
> 0 и < 100
```

0:

> Укажите процент больше 0.

100 и больше:

> После такой скидки цена станет нулевой или отрицательной.

---

### Повышение

Значение:

```text
> 0
```

---

# 49. Валидация фиксированной цены

Цена должна быть:

- числом;
- больше 0.

Ошибка:

> Укажите цену больше 0 ₽.

---

# 50. Валидация изменения на сумму

Сумма должна быть:

- числом;
- больше 0.

При вычитании необходимо заранее проверить все цены.

Если хотя бы одна станет `<= 0`:

> Для части товаров цена станет нулевой или отрицательной. Уменьшите сумму изменения.

Операцию блокировать.

---

# 51. Ошибки backup

### Не JSON

> Выберите backup-файл в формате JSON.

### Неверная структура

> Этот файл не является backup-файлом утилиты.

### Нет schemaVersion

> Не удалось определить версию backup.

### Неподдерживаемая версия

> Backup создан несовместимой версией утилиты.

### Backup пустой

> В backup нет данных для восстановления.

### Дублирующиеся UID

> В backup обнаружены повторяющиеся идентификаторы. Восстановление остановлено.

### Ни одного совпадения

> В текущем каталоге не найдено товаров из этого backup.

Блокировать восстановление.

---

# 52. Partial restore

Если часть UID не найдена:

не блокировать.

Показать предупреждение и список/количество пропущенных позиций.

---

# 53. Success criteria входного CSV

CSV считается успешно прочитанным только если:

- файл корректно распарсен;
- прочитаны headers;
- найден `Tilda UID`;
- найден `Parent UID`;
- найден `Category`;
- найден `Price`;
- найден `Title`;
- `Tilda UID` можно использовать как идентификатор;
- parent/variant structure может быть построена;
- категории извлечены;
- приложение может определить ценовые строки;
- приложение способно построить preview.

`Photo`, `Price Old`, `Editions` являются полезными, но отсутствие отдельного значения в конкретной строке не делает весь файл невалидным.

---

# 54. Success criteria расчета цены

Операция успешно рассчитана, если:

- категория существует;
- найден хотя бы один товар;
- найден хотя бы один price target;
- все изменяемые `Price` валидны;
- операция валидна;
- новое значение каждой цены > 0;
- применено необходимое округление;
- сформирован список разрешенных к изменению UID;
- сформирован preview;
- исходный файл не изменен.

---

# 55. Success criteria CSV export

Экспорт считается безопасным, если:

- количество строк совпадает с исходным;
- количество колонок совпадает;
- заголовки совпадают;
- порядок колонок сохранен;
- порядок строк сохранен;
- каждый `Tilda UID` сохранен;
- каждый `Parent UID` сохранен;
- все неизменяемые значения логически идентичны;
- изменилось только поле `Price`;
- `Price` изменилось только у whitelist UID текущей операции;
- число реально измененных price rows соответствует расчетному;
- сгенерированный CSV повторно успешно распарсился;
- повторная validation прошла без ошибок.

Только после этого кнопка скачивания доступна.

---

# 56. Success criteria backup

Backup считается валидным, если:

- содержит `schemaVersion`;
- содержит дату;
- содержит категорию;
- содержит описание операции;
- содержит хотя бы один item;
- каждый item содержит уникальный `Tilda UID`;
- каждый item содержит исходный `Price`;
- JSON успешно сериализован и повторно читается приложением.

---

# 57. Success criteria восстановления

Восстановление считается успешно рассчитанным, если:

- свежий CSV валиден;
- backup валиден;
- найден хотя бы один UID;
- каждому найденному UID назначается только `originalPrice`;
- `Price Old` остается текущим;
- остальные поля свежего CSV не изменяются;
- отсутствующие UID не создаются;
- новые товары не изменяются;
- итоговый CSV проходит полную safety validation.

- после refresh приложение начинает новую сессию.

Постоянной «памятью» об акции является скачанный пользователем backup-файл.

---

# 65. Приватность

Содержимое CSV не должно отправляться на hosting, backend, аналитику или сторонний API.

Все parsing и price calculations выполняются локально.

Допускается загрузка preview-изображений напрямую по URL `Photo` с CDN Tilda.

Содержимое CSV при этом никуда не передается.

---

# 66. Работа без API

Tilda API в MVP не используется.

Утилита не изменяет магазин сама.

Она только:

1. читает локальный CSV;
2. рассчитывает значения;
3. создает новый локальный CSV.

Изменения фактически попадают в магазин только после того, как пользователь вручную импортирует созданный файл через интерфейс Tilda.

---

# 67. Техническое правило безопасности

Запрещено:

- автоматически логиниться в Tilda;
- имитировать клики в панели Tilda;
- использовать undocumented Tilda API;
- отправлять запросы для изменения каталога;
- использовать browser automation.

MVP работает только через официальный CSV import/export flow.

---

# 68. Минимальная структура кода

Рекомендуется разделить логику как минимум на независимые модули:

```text
CSV parser
Catalog parser/model
Category extraction
Parent/variant resolver
Price calculator
Preview builder
Backup generator
Backup parser
Restore engine
Safety validator
CSV exporter
UI
```

Price calculations, CSV parsing и restore logic не должны быть зашиты непосредственно внутрь React-компонентов.

---

# 69. Чистые функции

Ключевые бизнес-операции должны быть реализованы как чистые функции, которые легко протестировать.

Например:

```text
calculatePrice()
roundPrice()
extractCategories()
resolveProducts()
resolvePriceTargets()
applyPriceOperation()
createBackup()
restorePrices()
validateCatalog()
validateOutput()
```

# 70. Тестовый fixture

Не добавлять полный production CSV ElleMexa в публичный репозиторий.

Для automated tests создать уменьшенные fixtures:

- 1 parent + несколько вариантов;
- товар в одной категории;
- товар в нескольких категориях;
- товар без вариантов;
- товар без цены;
- товар с разными ценами вариантов;
- поврежденный CSV;
- backup.

# 73. Тест Price Old

До:

```text
Price = 39990
Price Old = 62000
```

После −20%:

```text
Price = 31990
Price Old = 62000
```

---

# 74. Тест backup

После изменения:

`39990 → 31990`

backup должен содержать:

```text
originalPrice = 39990
```

---

# 75. Тест restore

Свежий CSV:

```text
Tilda UID: X
Price: 31990
```

Backup:

```text
Tilda UID: X
originalPrice: 39990
```

Результат:

```text
Price: 39990
```

Все остальные значения берутся из **свежего CSV**, а не из backup.

---

# 76. Тест partial restore

Backup содержит:

```text
UID A
UID B
UID C
```

Свежий CSV:

```text
UID A
UID C
```

Результат:

- A восстановлен;
- C восстановлен;
- B пропущен;
- показано предупреждение `1 позиция не найдена`.

---

# 77. Тест safety validation

Если в итоговом объекте случайно изменился:

`Photo`

экспорт должен быть полностью заблокирован.

Аналогично для любого поля, кроме разрешенного `Price`.

---

# 78. Проверка на реальном каталоге

Перед передачей клиенту необходимо проверить приложение на актуальном полном CSV ElleMexa.

Контрольные показатели определяются динамически.

На текущем эталонном файле ожидается корректная работа со структурой из parent-товаров и многочисленных дочерних вариантов. Варианты содержат собственные `Tilda UID`, `Parent UID`, `Price`, `Price Old`, `Quantity` и `Editions`.

# 79. Тестирование импорта в Tilda

Так как отдельного оплаченного тестового проекта может не быть, перед production-запуском рекомендуется создать в существующем каталоге временную тестовую категорию.

Например:

`PRICE_TOOL_TEST`

В нее добавить 1–2 тестовых товара.

Категория не должна использоваться в пользовательской навигации сайта.

На ней проверить полный цикл:

```text
экспорт
→ загрузка в утилиту
→ изменение
→ CSV
→ импорт в Tilda
→ проверка карточек
→ restore из backup
→ повторный импорт
```

Только после успешного теста использовать инструмент на коммерческих категориях.

MVP считается готовым только если:

- пользователь может открыть приложение на iPhone;

- получить успешную validation;
- увидеть динамический список категорий;
- выбрать одну категорию;
- снизить цену на %;
- повысить цену на %;

- увидеть preview;

# 88. Главное правило проекта

**Надежность важнее удобства и дизайна.**

Если приложение не может доказать, что в итоговом CSV изменилось только разрешенное поле `Price`, файл нельзя отдавать пользователю для скачивания.

Любое сомнительное состояние должно завершаться понятной ошибкой, а не попыткой «все равно сформировать файл».

Главная задача MVP:

> безопасно изменить цены выбранной категории и не затронуть ничего больше.
